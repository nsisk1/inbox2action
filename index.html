Architecture

Browser → POST /api/runs → Express server → 5-step pipeline → Postgres (runs, run_steps). Each step writes its status, timing and output to the database and pushes an event to the browser over Server-Sent Events, which colors the diagram above.

Retries: the AI step retries up to 3 times with exponential backoff (0.5s, 1s). Fallback: if all attempts fail, a rule-based extractor takes over and the step is marked degraded. Recovery: every finished step is saved, so if the server restarts mid-run, the run resumes from the last saved step instead of starting over.

Use the failure mode picker on the App tab to see each behavior live.
